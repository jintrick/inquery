# Issue: インストールスクリプトのテスト自動化と権限検証の徹底

## 背景と問題点
v0.3.0において、インストール自動化を謳いながら `install.sh` の実行権限不足によりユーザー環境で `./install.sh` が失敗するという致命的な検証漏れが発生した。
現在のテストフレームワーク (`scripts/run_tests.sh`) に、`install.sh` 自体の動作および権限のチェックが含まれておらず、配布品質の担保が不十分である。

## 解決策
インストールプロセスをテストスイートに組み込み、二度と「権限不足」や「実行失敗」を配布物に含めないようにする。
全スクリプトの実行権限を静的・動的に検証する仕組みを導入する。

対象ファイル:
- `scripts/run_tests.sh`: 権限チェックステップの追加
- `tests/test_install.sh` (新規): インストーラーの自動テスト
- `install.sh`: 権限およびパス処理の安定化
- `bin/inquery`, `scripts/*.sh`: 実行権限の正規化

## 実装内容詳細
1.  **権限の自動検証 (Static Check)**:
    - `scripts/run_tests.sh` に `check_permissions` 関数を追加する。
    - `exec_files` リストに含まれるファイルに対して実行権限（`+x`）の有無を検証し、欠落している場合はエラーを出力して中断する仕組みを実装した。
2.  **インストーラーの統合テスト (Dynamic Check)**:
    - `tests/test_install.sh` を作成し、`install.sh` を直接実行するテストを追加した。
    - `mktemp -d` により生成した一時ディレクトリを環境変数のオーバーライドに使用し、シンボリックリンクやデスクトップファイルの配置先を隔離（モック）した環境でテストを実行する。
    - インストール実行後、対象ディレクトリにファイルが存在し、かつ実行可能であることを検証する。
3.  **ユーザー同等環境の再現**:
    - `tests/test_install.sh` 内で `./install.sh` として呼び出すことで、実際のユーザー環境と同様の権限チェックを動的に行う。

## 規約準拠 (Rule Compliance)
- `comment-preservation.md`: 既存の `install.sh` や `run_tests.sh` のコメントを維持し、追加した検証ロジックに意図を明記した。
- `no-temp-files-in-root.md`: テストで使用する一時ディレクトリは `/tmp` 配下に作成し、終了時に確実に削除するように実装した。
