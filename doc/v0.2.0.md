# Issue: テストフレームワークの導入と品質ガードレールの構築

## 背景と問題点
現状、`inquery` プロジェクトには自動テストが存在せず、機能追加や修正時に既存機能（URL置換、スクリプト実行、アクションのフィルタリング等）が破壊されていないかを手動で確認する必要がある。また、Ubuntu/X11環境に依存する `zenity` を多用しているため、開発環境（CI環境を含む）での動作確認が困難である。BashとPythonの混成プロジェクトにおいて、一貫したコード品質を維持するための静的解析も不足している。

## 解決策
以下のツール群を導入し、テストおよび静的解析を自動化する。
- **静的解析**: `ruff` (Python) と `shellcheck` (Bash) の導入。
- **ユニットテスト (Python)**: `pytest` を使用し、`lib/filter.py` および `lib/executor.py` のロジックを検証。
- **統合テスト (Bash)**: `zenity` をモック化する手法を導入し、`bin/inquery` および `lib/ui.sh` の挙動を非対話的に検証。
- **テストランナー**: すべてのチェックをワンコマンドで実行する `scripts/run_tests.sh` の作成。

## 実装内容詳細
### 1. 静的解析の整備
- `pyproject.toml` に `ruff` の設定を追加する。
- `scripts/run_tests.sh` 内で `shellcheck` を実行するように構成する。対象は `bin/inquery` および `lib/` 以下のスクリプト。

### 2. Python ユニットテスト (`pytest`)
- `tests/test_filter.py`: 
    - `filter_actions(actions, query)` 関数のテスト。
    - 大文字小文字の区別なし、部分一致、空クエリ時の挙動を検証。
- `tests/test_executor.py`:
    - `type: "url"` のURL置換ロジックのテスト。`quote_plus` によるエンコードが正しいか確認。
    - `type: "script"` の引数置換ロジックのテスト。
    - `subprocess.Popen` が正しいコマンドライン引数で呼び出されることを `unittest.mock` で検証。

### 3. Bash 統合テスト (Zenity Mocking)
- `tests/test_ui.sh` を作成。
- テスト内で `zenity()` 関数を定義して元のコマンドを隠蔽（Mocking）し、呼び出された際の引数をファイルに記録して検証する。
- `config/actions.json` の読み込みパスの優先順位（カレントディレクトリ vs `~/.config/inquery/`）を、一時的な環境変数 `HOME` を操作して検証。

### 4. テストランナーの作成
- `scripts/run_tests.sh` を作成。

## 規約準拠 (Rule Compliance)
- `comment-preservation.md`: テスト用フックを `lib/` 配下のファイルに追加する場合、既存の設計意図を説明するコメントを削除せず、必要に応じて更新する。
- `no-temp-files-in-root.md`: テスト中に生成する疑似設定ファイルやログは、`/tmp/inquery-test.$$` 等の一時ディレクトリ内に作成し、`trap` コマンド等を使用して終了時に必ず削除する。

## テスト
- テスト対象: URL置換ロジック (`executor.py`)
  - 内容: 特殊文字（`&`, `?`, スペース）を含むクエリのエンコード。
  - 方法: `pytest` で複数のクエリパターンを流し、期待されるURL文字列と一致するかアサートする。
- テスト対象: アクション選択フロー (`ui.sh`)
  - 内容: ユーザーがキャンセル（Esc）した場合の挙動。
  - 方法: `zenity` モックが終了ステータス `1` を返すように設定し、呼び出し元のスクリプトが正常に終了することを確認。
- テスト対象: 静的解析
  - 内容: 未定義変数や未使用インポートの検知。
  - 方法: 意図的にエラーを混入させ、`scripts/run_tests.sh` が失敗することを確認。
