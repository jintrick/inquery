# Issue: 配布準備（XDG準拠、堅牢なパス解決、デスクトップ統合）

## 背景と問題点
現在の実装は実行時の相対パスに依存しており、システム全体へのインストールが困難である。また、設定ファイル（actions.json）がプロジェクト内に固定されており、ユーザーごとのカスタマイズが XDG Base Directory 規約に準拠していない。

## 解決策
- **XDG準拠のフォールバック実装**: アプリ側でのファイル生成は行わず、ユーザー設定からシステムデフォルトまでを順番に探索する堅牢な読み込みロジックを実装する。
- **絶対パスによるロード**: スクリプト内での `lib` および `config` ディレクトリの特定を、実行ファイルからの絶対パス解決に切り替える。
- **デスクトップ統合**: `.desktop` ファイルのサンプルを同梱し、ユーザーがランチャーに登録できるようにする。

## 実装内容詳細

### 1. パス解決の堅牢化 (`bin/inquery`)
- 実行ファイルの場所からプロジェクトのルート（`APP_ROOT`）を特定する。
  ```bash
  # Ubuntu (Bash) 前提のシンプルな解決
  APP_ROOT=$(dirname "$(dirname "$(readlink -f "$0")")")
  ```
- `lib/ui.sh` を絶対パスで呼び出す。

### 2. 設定ファイルの探索ロジック (`lib/ui.sh`)
以下の優先順位で `actions.json` を探索し、最初に見つかったものを採用する。
1.  `${XDG_CONFIG_HOME:-$HOME/.config}/inquery/actions.json` （ユーザーカスタム）
2.  `$APP_ROOT/config/actions.json` （同梱のデフォルト）
3.  `$APP_ROOT/config/actions.json.example` （開発用バックアップ）

どれも見つからない場合のみ `zenity --error` を表示して終了する。

### 3. executor.py の絶対パス指定
- `ui.sh` 内で `python3 "$APP_ROOT/lib/executor.py"` として呼び出すよう修正。

### 4. アセットの整備
- `assets/inquery.desktop.example` を作成。
- README.md に以下のインストールガイドを追加：
    - `/usr/local` への配置例。
    - 設定ファイルをカスタマイズする場合のコピー先（`~/.config/inquery/actions.json`）。
    - ショートカットキー割り当ての推奨設定。

## テスト

### 1. フォールバック検証
- **手順**:
  1. `~/.config/inquery/actions.json` を削除。
  2. `bin/inquery` を起動し、同梱のデフォルトアクションが表示されることを確認。
  3. `~/.config/inquery/actions.json` を作成し、別のアクションを定義。
  4. 再起動し、作成したアクションのみが表示されることを確認。

### 2. パス非依存テスト
- **手順**:
  1. プロジェクト外のディレクトリから `.../bin/inquery` を実行。
  2. 正しく `lib/ui.sh` や `lib/executor.py` がロードされることを確認。

## Appendix: 変更の理由
- **自動生成の廃止**: Bash スクリプトによる `mkdir` や `cp` は副作用（権限エラー等）を伴うため、読み取り専用のフォールバックロジックにする方が堅牢。
- **readlink -f**: Ubuntu ターゲットにおいて、シンボリックリンク経由の実行でも正しく `APP_ROOT` を取得するため。
