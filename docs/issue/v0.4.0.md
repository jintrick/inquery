# Issue: インストール時の初期設定自動配置（UXの改善）

## 背景と問題点
現在の `install.sh` はバイナリとデスクトップファイルの配置のみを行い、設定ファイル (`~/.config/inquery/actions.json`) の作成をユーザーの手作業に委ねている。
「不干渉」を優先するあまり、インストール直後にツールを起動しても「設定ファイルが見つかりません」というエラー（またはフォールバックへの依存）が発生し、ユーザー体験が著しく損なわれている。

## 解決策
インストールプロセスに「初期設定のプロビジョニング（供給）」を追加する。既存の設定がある場合は一切関与せず、存在しない場合にのみデフォルト設定を配置する「親切かつ安全な」設計に改める。

## 設計上の考慮点 (Coding Rules)
### `comment-preservation.md`
- `install.sh` に新規追加するプロビジョニングロジックには、動作の意図（「ユーザー設定を尊重し、存在しない場合のみデフォルトを配置する」等）を明確にするコメントを付与する。
- `tests/test_install.sh` の新規テストケースにも、各検証シナリオの目的をコメントで記述し、メンテナンス性を確保する。

## 実装手順 (Atomic Implementation Steps)
1. **`install.sh` の修正**:
   - `XDG_CONFIG_HOME` (未設定時は `$HOME/.config`) を基準に `CONFIG_DIR="$HOME/.config/inquery"` を定義する。
   - `mkdir -p "$CONFIG_DIR"` を実行してディレクトリを作成する。
   - `CONFIG_FILE="$CONFIG_DIR/actions.json"` が存在しない場合 (`[ ! -f "$CONFIG_FILE" ]`) に限り、`$APP_ROOT/config/actions.json` をコピーする。
   - コピー実行時にユーザーへ通知する `echo` 文を追加する。
2. **`tests/test_install.sh` の更新**:
   - **新規配置テスト**: `fake_home` 下に設定ファイルがない状態で `./install.sh` を実行し、ファイルが配置されることを確認する。
   - **内容整合性テスト**: 配置されたファイルが `$APP_ROOT/config/actions.json` と同一であることを `diff` で検証する。
   - **上書き防止テスト**: 既存の `actions.json` がある状態で `./install.sh` を実行し、内容が変更されないことを検証する。

## テスト・ゴール要件 (Definition of Done)
- [x] `./install.sh` 実行後、`~/.config/inquery/actions.json` が（未存在時のみ）適切に作成される。
- [x] 既に設定ファイルが存在する場合、`./install.sh` を再実行してもファイル内容が保護（維持）される。
- [x] `tests/test_install.sh` に「新規配置」「上書き防止」のテストが追加され、全てパスする。
- [x] `install.sh` およびテストコード内に、`comment-preservation.md` に基づく適切な解説コメントが含まれている。
- [x] 既存のインストール機能（バイナリ配置、デスクトップ統合）が正常に動作し続けている。
